# Crawler Ingest Dry-Run

## 1. Purpose

The ingest dry-run sits between crawler v2 schema readiness and real notice ingest. It turns fixture or collector-like output into planned v2 table operations without connecting to Supabase by default and without writing to DB.

It reduces risk by proving:

- fixture items can be mapped to the normalized crawler schema.
- generated DB columns are excluded from payloads.
- canonical notice, URL alias, occurrence, target, asset, keyword, and error policies are visible before any write path exists.
- output reports can be reviewed by ChatGPT or a human before the project moves toward real collector output.

## 2. Current Preconditions

- `crawler_notice_sources` sample rows are prepared for `cau_001`, `cau_002`, and `yonsei_060`.
- The personal dev DB has reportedly seeded the 605 CSV `org_unit_id` values.
- `crawler_source_targets` sample rows are reportedly applied for `cau_001 -> 719`, `cau_002 -> 720`, and `yonsei_060 -> 46`.
- Full 613 source-target apply is not assumed.
- This dry-run does not execute crawler collection, source sync apply, target apply, or notice ingest.

## 3. Ingest Input Contract

The dry-run fixture accepts:

- `run.run_key`, `run.started_at`, `run.mode`, `run.parser_version`
- `sources[].source_key`
- `sources[].items[].title`
- `discovered_url`, `canonical_url`, optional `final_url`
- `published_at`
- `body_text`, `body_html`, `body_quality`
- `assets[]` with `asset_type`, `filename`, `source_url`, `content_type`
- `warnings[]`

The implementation intentionally keeps this close to collector output but remains fixture-first.

## 4. V2 Table Mapping

| Input / derived field | V2 table | Notes |
| --- | --- | --- |
| run metadata | `crawler_runs` | Uses `run_ref` placeholder; DB `id` is generated later. |
| per-source counts | `crawler_source_results` | Uses `run_ref` and `source_ref`; source DB id is resolved only in real ingest. |
| title, canonical URL, body, posted date | `crawler_notices` | Upsert candidate by `canonical_key`. |
| canonical/discovered URLs | `crawler_notice_url_aliases` | `url_hash` is generated by DB and excluded. |
| source discovery path | `crawler_notice_occurrences` | `discovered_url_hash` is generated by DB and excluded. |
| source-key CSV target | `crawler_notice_targets` | Uses local CSV `source_key -> org_unit_id`; DB readiness can be checked read-only. |
| attachments/images | `crawler_notice_assets` | `source_url_hash` is generated by DB and excluded. |
| keyword evidence | `crawler_keyword_matches` | Simple dry-run keyword extraction only. |
| body warnings / validation warnings | `crawler_errors` | Captures dry-run validation warnings as planned errors. |

## 5. Key Strategy

- Canonical notice key priority:
  - native post ID if present: `<source_key>:native:<id>`
  - canonical/final/discovered URL hash
  - normalized title + posted date hash fallback
- URL aliases are deduped by dry-run `notice_ref + url`.
- Occurrences are per source item and preserve discovered URL provenance.
- Targets come from `data/notice-sources.csv` and are deduped by `notice_ref + org_unit_id`.
- Assets are deduped by `notice_ref + asset_kind + source_url`.
- DB generated columns are never included in planned payloads:
  - table identity IDs
  - `url_hash`
  - `discovered_url_hash`
  - `source_url_hash`
- Dry-run placeholders such as `run_ref`, `source_ref`, `notice_ref`, and `occurrence_ref` are not DB columns.

## 6. Dry-Run Output Contract

The script returns:

- `summary` counts
- `schema_blockers`
- `skipped`
- `planned_operations` grouped by v2 table
- `db_check` when explicitly requested

Operation states:

- `would_insert`
- `would_upsert`
- `would_skip` is represented in `skipped`
- `would_error` is represented by planned `crawler_errors`

Console output is summary-first and prints a redacted notice preview. `--json` emits the full report. `--out <path>` saves the JSON report.

## 7. Safety Rules

- No DB write.
- No production access.
- No secret output.
- No actual crawler execution by default.
- No `--apply`, `--write`, or `--commit` option.
- `--check-db` is read-only and requires personal-dev guards:
  - `--yes-i-am-using-personal-dev-db`
  - `PERSONAL_DEV_SUPABASE_CONFIRM=1`
  - `SUPABASE_URL`
  - `SUPABASE_SERVICE_ROLE_KEY`

## 8. Open Risks

- Real collector output shape can vary by source.
- HTML body quality differs by source.
- Attachment extraction may fail or produce partial metadata.
- URL-only canonicalization can lose provenance when schools rewrite URLs.
- Full 613 source-target rows are not assumed to be applied in DB.
- Keyword matching is intentionally lightweight and only proves payload shape.

## 9. Go/No-Go Criteria for Real Ingest Later

GO only when:

- fixture dry-run passes without schema blockers.
- read-only DB check passes for selected source keys.
- planned payloads match the v2 schema.
- sample source-target joins are available.
- duplicate, change, alias, asset, and error policies are documented.
- collector-output adapter has been tested with real but non-ingested output.

NO-GO when:

- missing source rows, source targets, or org units remain.
- schema blockers are present.
- generated DB columns appear in payloads.
- a write path is requested before dry-run report review.

## 10. Commands

Dry-run:

```bash
node scripts/ingest-crawler-run-dry-run.mjs \
  --fixture fixtures/crawler-ingest-dry-run/sample-notices.json \
  --source-key cau_002 \
  --limit 5
```

JSON report:

```bash
node scripts/ingest-crawler-run-dry-run.mjs \
  --fixture fixtures/crawler-ingest-dry-run/sample-notices.json \
  --source-key cau_002 \
  --limit 5 \
  --json \
  --out reports/ingest-dry-run-sample.json
```

Read-only personal-dev DB check:

```bash
PERSONAL_DEV_SUPABASE_CONFIRM=1 \
SUPABASE_URL=... \
SUPABASE_SERVICE_ROLE_KEY=... \
node scripts/ingest-crawler-run-dry-run.mjs \
  --fixture fixtures/crawler-ingest-dry-run/sample-notices.json \
  --source-key cau_002 \
  --limit 5 \
  --check-db \
  --yes-i-am-using-personal-dev-db
```
